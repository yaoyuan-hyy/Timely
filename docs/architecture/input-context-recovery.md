# 输入上下文与恢复

## 状态分离

当前 UI 从 `/api/input-decision` 获取结构化决策，`lib/write-session.ts` 管理会话，`lib/write-draft.ts` 合并已验证字段。失败不再只留下聊天气泡。

| 状态 | 保存内容 | 权限 |
| --- | --- | --- |
| `writeSession.draft` | 已通过校验的字段及来源、草稿版本 | 只能形成预览 |
| `writeSession.recovery` | 未决用户原话、每轮时间与 ID、版本、原因、问题、过期时间 | 只能供重新解析，不是有效记录 |
| `pendingConfirmation` | 完整记录提案、原记录快照 | 无未决恢复任务时，用户确认才能提交 |
| `messages` | 展示用聊天历史 | 不整段发送给模型，不作为写入依据 |

未决上下文不保存失败的模型输出或凭模型猜出的字段，也不发送用户记录集合。模型只接收当前输入、必要草稿投影、记录选择信息、查询澄清和未决原话。

## 生命周期

1. 网络、schema、字段验证失败，或意图需要澄清时，保存原始用户输入及该轮 `referenceNow`。
2. 下一轮返回 `recovery: { id, revision, mode }`，明确 `continue` 或 `replace`。缺失或旧版本不得自动执行。
3. `continue` 联合未决原话重新提取字段；应用根据实际草稿决定 create/revise 和草稿 ID，不把 recovery ID 当成记录或草稿 ID。`replace` 放弃旧未决输入，但已有有效草稿仍受确认/取消保护。
4. 合并成功后消费 recovery，得到缺字段草稿或待确认提案。原提案存在但补充失败时，UI 和确认 Tool 都拒绝保存旧提案。
5. 取消、清空聊天和刷新清除未决写入状态。有效期为最后一次保留后的 15 分钟，在下一次输入时检查；不会在后台自动写入。

最多保留 4 轮、总计 12000 字符，每轮最多 4000 字符。达到上限时保留已有上下文，明确要求取消后完整重述，不默默截去最早的日期或其他信息。失败重试继续使用原输入与原时间；异步 staging 比较当前会话和提交前版本，取消或新的会话不会被旧响应恢复。

## 字段来源和时间

字段默认从本轮 `input` 的 `evidence` 取证；引用旧轮次时带 `turnId`。若模型漏写 turnId，但证据在本轮不存在且唯一命中一条未决原话，程序可唯一定位来源；多处命中或找不到来源则拒绝。`replace` 无法访问旧来源。

相对日期由本地代码按该证据来源轮次的时间转换。例如 9 月 7 日 23:59 的“昨天午饭”，在 9 月 8 日 00:01 补充金额，“昨天”仍解析为 9 月 6 日。本轮明确的新日期使用本轮时间。

未决原话的覆盖检查可发现只补金额而完全遗漏前一轮的输出；完整重述可以用两轮都存在的证据。它不是自然语言语义正确性的证明：模型仍可能提取错误类别、漏掉同一句里的某个条件，最终预览与评测仍然必要。

## 有界重新解析

恢复场景输出未通过 schema 或上下文覆盖校验时，适配器最多再请求一次，携带程序产生的 `validationIssue`。两次请求共享 15 秒截止时间，不因修复延长到无限等待，也不因网络错误反复调用。修复后仍不合格则保留上下文并追问。没有引入 few-shot 对话或样例专用规则。

## 验证方式

- `npm run test:write-v2`：失败恢复、草稿保护、来源引用、跨午夜、版本拒绝、新话题隔离、过期、容量、取消、确认 Tool 与单次修复。
- `scripts/eval-input-recovery.ts`：先注入已知故障/澄清，再由真实 DeepSeek 解析补充答案，测量条件恢复能力；不能将其等同于一般准确率。
- `scripts/eval-write-flow-v2-live.ts`：保持原七条样例及答案，对照整体多轮表现。结果见 `docs/evals/input-recovery-live-results.json` 和 `docs/evals/write-flow-v2-after-recovery.json`。


## 2026-09-12：纠正覆盖与统一来源判定

`continue` 支持可选 `recovery.superseded: [{ turnId, evidence, fields }]`：模型声明某轮原话被本轮纠正/重述覆盖，列出本轮 patch 的覆盖字段。程序要求轮次存在且不重复、声明逐字引自本轮、字段确实存在且其 evidence 包含在该声明中，不允许用旧 turnId 冒充新覆盖字段。未被覆盖的轮次仍须有有效旧来源引用，否则阻止确认。

覆盖声明表达语义关系，不将失败字段变成有效草稿，也不免除金额、日期、类别和字段来源校验。单字段纠正仍须重新提取其他有效旧信息；已有有效草稿中未修改字段由程序保留。无法判断是否遗漏应澄清。程序能检查证据引用和字段结构，不能仅靠字符串检查证明模型完整理解了每个旧字段，因此仍需多轮评测和用户预览确认。

校验和字段应用共用 `resolvePatchSource`：显式 turnId 优先；无 turnId 且本轮包含 evidence 时归本轮；否则只有唯一旧来源匹配才可归旧轮。相同词出现在新旧两轮时，不再误算成已处理旧轮。本轮同词不继承旧日期的时间参照。

模型仍需返回 recovery id/revision；既有 stale 检查保留。恢复时 create/revise 和草稿身份已由 session 按当前状态决定。本轮没有扩大到全部模型协议迁移。
