# Timely 当前产品说明

更新：2026-09-12。阶段：可运行原型，真实用户验证待开展。

## 问题与假设

假设：已有记录习惯的人在零碎场景下，希望直接说出时间、事项或金额，减少填写表单的步骤。自然语言是否更快、预览确认是否过重，尚未通过真实用户数据验证。

核心任务：记录事件、独立记账、查回记录。目标人群优先选择已有记账/日程习惯且愿意核对结果的人，不将所有人视为目标用户。

## 当前流程

输入 → 意图/字段解析 → 缺失信息追问或纠错 → 可核对的预览 → 明确确认 → 单条保存 → 日历/流水查回。查询通过只读决策与确定性执行返回结构化结果。

写入需要确认；失效模型字段不进入有效草稿；失败补充阻止确认旧预览；重复记录提示用户选择；已保存数据与异步请求结果按当前状态合并。查询不改变 records。

## MVP 范围

日程与流水、多轮补充/纠正、受限查询、取消/恢复日程、本地备份。时区 Asia/Shanghai，本地存储，无账号/云同步/提醒通知/任务系统，语音按钮未接入。

模型只理解和生成结构化决策，不确认保存、不接收整库记录、不计算最终查询金额。失败时可保留原话并重试，有限本地回退单独标识。

## 待验证

1. 用户能否区分预览与已经保存？
2. 短答、纠正、追问是否符合用户理解？
3. 相比原有工具，完成一条正确记录是否更省操作？
4. 模型失败后用户是否能独立恢复？
